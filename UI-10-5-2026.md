# UI-10-5-2026 — UI Branch Charter

Branch: `UI10-5-2026` (cut from `main` on 2026-10-05)

## What we are building

**Flowstate: a professional real-estate underwriting workstation.**

Design character:

- institutional
- modern
- precise
- data-dense
- calm
- high-trust
- analytical
- premium

NOT:

- playful SaaS
- crypto dashboard
- consumer real-estate portal
- generic AI dashboard
- excessive cards
- excessive pills
- unnecessary gradients
- decorative icons
- enormous whitespace
- tiny low-contrast metadata
- visual decoration without informational meaning

Test for every change: does it help an underwriter read, compare, or decide
faster? If it is only decoration, cut it.

## Scope

This branch is **UI only**. Claude owns:

- Component design, creation, and editing
- Typography, spacing, layout, responsive behavior
- Visual polish and accessibility

Work lives in `apps/dashboard` (Next.js, React 19, Tailwind 3, shadcn-style
`src/components/ui`).

## Off limits

- **All backend wiring.** No API calls, routes, hooks that fetch or save,
  state/atoms logic, server actions, auth, database, or secrets.
- The evaluator / harness / ARV math (`apps/api`, `packages/shared`, `docs/*HARNESS*`, `docs/EVAL-*`).
- **The theme.** Do not change colors, tokens, fonts, or presets
  (`globals.css`, `tailwind.config.ts`, `layout.tsx`) unless the user says so.
  Build inside the existing theme.
- Deploys. Only when the user says so.

If a UI change needs any of the above, stop and flag it.

## Theme snapshot (read-only review, 2026-10-05)

Reviewed in code and in screenshots (light + dark, landing + 6 dashboard pages).

**Feel:** quiet, monochrome, engineering-tool look. Hairline borders, small
radius, dense data. One loud color: green brand.

**Color** (HSL CSS variables in `globals.css`, zero hue in the neutral ramp)
- Presets: `led` (default, warm paper `#edeae5`-ish), `outdoor` (max-contrast light), `night` (near-black `#0a0a0a`), `dawn` (cool slate dark).
- Tokens: `background`, `foreground` (+secondary/tertiary), `card` (+hover), `muted`, `accent`, `border`, `input`, `ring`, `primary` (inverted: dark button on light, light on dark), `destructive`, `brand`.
- `brand` = green `134 100% 41%`. Used for the hero line, ARV evidence edge, positive numbers, active dots.
- Status colors in use: emerald (good), amber (attention), red (bad/excluded), blue/purple/orange chips on comp cards.

**Type**
- Sans: Inter (variable, self-hosted). Serif: Source Serif 4 (used for the form question on the landing page; italic). Mono: `--font-mono` for micro-labels.
- Custom scale in Tailwind: `display-lg/display/display-sm`, `heading-lg/heading/heading-sm`, `body-lg/body/body-sm`, `caption/caption-sm`. Use these, not raw `text-sm`.
- `.mono-label`: tiny uppercase tracked eyebrow. Used on landing and report headers.
- Money and big numbers: bold, tight tracking.

**Shape and surfaces**
- `--radius: 0.375rem` (6px). `lg/md/sm` derive from it. Cards are thin-bordered, no shadow in dark.
- Light "glass" classes (`glass-result`, `glass-comp`, `glass-stat`, `glass-input`, `glass-accent`) go flat and outlined in dark. Playground only.
- Dark playground bg: dot grid. Corner diamonds (`corner-accents`) on some cards.
- Landing: bordered cell grids with `01 / 02` numbering, left aligned, lots of air.

**Layout**
- Dashboard: left sidebar (collapsible) + page header + content. Mobile: bottom nav.
- Analyze page: map left, subject + comps grid right, resizable pane; valuation strip under the map.
- Results use container queries (`props-pane`, `comps-grid`, `hero-stats`), so cards respond to pane width, not the screen.
- Print/PDF has its own styles. Do not break them.

**Consistency notes (things to know, not things to fix yet)**
- Page headers differ page to page: some have an icon tile (Evaluation Settings), some a mono eyebrow (Reports), some plain (Overview, API Hub).
- Overview stat cards use tinted icon tiles (green/red/blue) that the rest of the app does not use.
- Overview cards use a larger radius than the 6px used elsewhere.
- Status pills (`Active`, `Attention`) are green/amber outlined; comp chips are solid and multi-colored.
- Body text is small (11–13px) in dense areas. Check contrast before shrinking more.
- Dark mode forces `.dark`; light default is the warm `led` preset, so test all presets when changing a component.

## Hard rule: no blind UI changes

**Not allowed:**

```
read code -> edit CSS -> tests pass -> "done"
```

Passing tests or typecheck never means a UI change is done. A UI change is
done only after it has been seen in the running app.

**Required workflow for every UI change:**

```
Inspect existing component
  -> Understand the surrounding design system
  -> Implement
  -> Run the application
  -> Open the actual page
  -> SCREENSHOT
  -> Visually inspect the result
  -> Compare against requirements
  -> Identify visual defects
  -> Modify
  -> SCREENSHOT AGAIN
  -> Verify responsive state
  -> Finish
```

Notes:

- "Finish" means: before and after screenshots checked, light and dark checked,
  and a mobile width checked.
- Dev server: `http://localhost:3100/dev-login` (lands in the dashboard).
- Screenshots go through headless Playwright with writes blocked. The report
  page autosaves on load, so block non-GET calls first.
- If a page cannot be opened or screenshotted, say so. Do not report it done.
- Every change must also pass the checklist in `UI-SCREENSHOT-REVIEW.md`, and
  its result is logged there.

## How to run the tests

Unit (all dashboard tests, includes the new ones):

```
npm run test -w @flowstate-api/dashboard
```

End-to-end UI tests (no model or API keys needed). The dashboard and its API must be running; the test user's password comes from the environment and is never committed:

```
cd apps/dashboard
LD_LIBRARY_PATH=$HOME/.local/lib/playwright-deps \
APP_URL=http://localhost:3100 \
E2E_USER_LOCAL_PASSWORD=... \
npx e2e run --config e2e.ui.config.ts tests/auth.setup.e2e.ts tests/ui-polish.e2e.ts
```

Notes: the run rewrites the tracked file `apps/dashboard/.e2e/report.json`; restore it before committing (`git checkout -- apps/dashboard/.e2e/report.json`). The first sign-in after the dev server restarts can be slow and time out once; run again.

## Rules

- One branch for all UI work. No stacked side branches.
- Follow existing patterns in `src/components` before adding new ones.
- Reuse `src/components/ui` primitives first.
- Check light and dark (and mobile) with screenshots. Block writes first when loading the report page: it autosaves on load.
- Typecheck with `npx tsc --noEmit` (or `npm run typecheck` in `apps/dashboard`).
- Do not build or deploy after each change.
- Never merge `main` into this branch. Rebase if it goes stale.
- Land via PR into `main`, squash merge.
